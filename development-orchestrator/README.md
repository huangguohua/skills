# Development Orchestrator

轻量级开发编排 Skill，负责在架构设计完成后协调前后端开发流程。

## 快速开始

1. 确保 `requirements.md`、`prototype.md`、`design.md`、`tasks.md` 均已通过用户确认
2. 触发本 Skill（关键词：开始开发 / 按 tasks.md 编排 / 启动前后端开发）
3. 编排层自动读取 `tasks.md`，判断依赖关系，按序触发子 Skill
4. 开发完成后提示用户进入测试阶段

## 编排流程图

```
tasks.md (已确认)
    |
    v
+-------------------+
| 读取 & 解析任务    |
| 识别前后端 & 依赖  |
+-------------------+
    |
    v
+-------------------+     +---------------------+
| 后端任务存在？     |--是-->| 触发 backend-dev    |
+-------------------+     +---------------------+
    |                              |
    v                              v
+-------------------+     +---------------------+
| 前端任务存在？     |--是-->| 触发 frontend-dev   |
| (检查依赖是否满足) |     | (依赖满足后触发)     |
+-------------------+     +---------------------+
    |                              |
    v                              v
+-------------------------------------------+
| 汇总变更 -> 更新 CHANGELOG.md              |
+-------------------------------------------+
    |
    v
+-------------------------------------------+
| 提示用户进入测试 (testing-expert)          |
| [不自动触发 delivery-code-review]          |
+-------------------------------------------+
    |
    v
+-------------------------------------------+
| 若有修复任务 -> 读取报告 -> 分派修复       |
| -> 回到子 Skill -> 更新 CHANGELOG          |
+-------------------------------------------+
```

## 目录结构

```
development-orchestrator/
  SKILL.md                  # Skill 定义与编排规则
  config.json               # 配置文件
  README.md                 # 本文件
  references/
    gotchas.md              # 常见陷阱
    domain-rules.md         # 领域规则
    examples.md             # 示例
    glossary.md             # 术语表
  assets/
    changelog-template.md   # CHANGELOG 模板
    checklist-template.md   # 编排检查清单
  scripts/
    check_tasks_status.py   # 任务状态检查脚本
  logs/
    README.md               # 日志格式说明
  outputs/
    .gitkeep
```

## 核心原则

- **只编排不编码**：编排层绝不直接修改业务代码
- **闸门严守**：上游产物未确认不启动，下游审查不自动触发
- **变更可追溯**：每轮操作必须更新 CHANGELOG 并记录编排日志
