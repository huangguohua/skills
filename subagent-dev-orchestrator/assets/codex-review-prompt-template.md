# codex:rescue 复审提示词模板

> 主会话用 Agent 工具调用 `subagent_type: "codex:codex-rescue"` 时填充为 prompt。
> 切勿用 `Skill(codex:rescue)`（会重入命令并挂起会话）。

```
只读代码复审，不要修改任何代码、不要 --write。仅检查并报告问题。

【复审范围】（本任务 T<N> 本轮改动）
- 文件：<改动文件清单，或 diff 范围>

【对照基准】
- 契约：模式 A = design.md <相关章节>；模式 B = 需求描述原文 + tasks.md T<N> 口述契约（API 字段/错误码/数据模型必须一致）
- 规范：<coding_standards_path / backend_gotchas_path / frontend_gotchas_path>
- 验收标准：tasks.md T<N>

【检查重点】
- 功能正确性、边界与异常、并发/幂等/事务
- 与 design.md 契约是否一致（字段、错误码、状态机）
- 安全（注入、越权、敏感信息）、数据正确性
- 规范与坑点文档的违背项

【输出格式】（逐条，必须带级别）
对每个问题输出一行：
  [级别] 文件:行 — 问题描述 — 修复建议
级别定义：
  P0 = 阻断性（编译/构建失败、功能不可用、数据错误、安全漏洞、契约破坏）
  P1 = 严重（明显逻辑错误、契约不符、重大规范违背、边界缺陷）
  P2 = 次要（可读性/命名/非阻断优化建议）
若无 P0/P1，请明确写一行："未发现 P0/P1 问题"。
```

## 主会话如何用返回结果

- 解析 codex 输出中每条问题的级别。
- 存在任一 **P0 或 P1** → SendMessage 把这些条目回传给本任务的子 agent 修复，修完再次复审。
- 仅剩 **P2** 或无问题 → 该任务通过；P2 记入 CHANGELOG 遗留项。
- 若 codex 返回空（CLI 未就绪）→ 不算通过，提示用户 `/codex:setup`。
